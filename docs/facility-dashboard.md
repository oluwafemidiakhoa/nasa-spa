# Facility evidence dashboard (v0.6)

Contract: offline-first inspection of v0.5 evidence bundles. The browser checks the exact bundle digest (optionally against an independently retained digest), each component digest, archived source digest, pinned declared method fingerprints, configuration bounds, archive counts and exact same-method JavaScript replay. It does not execute the independent Python verifier. A matching browser result is consistency evidence, not authenticated provenance or scientific validation. Whole-bundle replacement remains possible without a separately retained digest. Only local files are read; the demo uses a committed, explicitly synthetic bundle. No remote data calls, external libraries, persistence, geolocation, or analytics are added. Use a trusted local checkout and localhost or HTTPS; do not upload private inputs to an untrusted website. Limits: 26 MB bundle, 3 MB archive, 32 KiB configuration, 16 MB report, 2 MB source, 64 nested JSON containers, 25 facilities. Reject duplicate JSON keys, malformed UTF-8, invalid or noncanonical base64, unexpected method fingerprints, inconsistent digests, mismatched results and invalid configuration. A failed or superseded load clears results. Display at most 50 matching events per page. Match counts are not risk scores; coverage is unknown and no match is not safety.

Run `python -m http.server 8000` from the repository root and open `http://localhost:8000/facilities.html`. Load the synthetic example, or select a v0.5 JSON bundle and optionally paste a separately saved SHA-256. Select each facility and page through its matching observations. The original archive/config/report can be checked independently with `python scripts/earth_evidence.py verify BUNDLE.json --expected-sha256 DIGEST`. Retain the original bundle; the interface does not modify it.

Acceptance: reproduce the three-facility synthetic result, reject corrupt components, duplicate keys, changed result with recomputed hash, incorrect independent digest, altered method identifiers, malformed data, and unsupported schema. In Chromium, verify demo load, filtering, file import, anchor failure, stale-result clearing, accessible status and mobile layout. No live NASA retrieval, real-world risk assessment or production deployment is in scope.
