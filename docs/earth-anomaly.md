# Gaia Earth observation screening v0.8

## Locked descriptive method

Input: one retained v0.5 bundle, replayed by the v0.7 historical engine. Use the latest fully contained UTC date (00:00:00.000 through 23:59:59.999 inclusive) as target. Use exactly the previous 19 consecutive full UTC dates as baseline; no target or later observations enter it. Each of these 20 dates must contain at least five eligible point rows in the snapshot. Otherwise abstain (INSUFFICIENT_BASELINE or INSUFFICIENT_OBSERVATIONS). A partial date never qualifies. No alternative window, threshold, or facility is selected based on results.

For each facility compare the fraction of eligible point rows inside its fixed radius, not an occurrence rate or hazard probability. Compare integer cross products (no rounded fractions). Count baseline days with fraction greater than or equal to the target. Report rankNumerator = 1 + that count, rankDenominator = 20, and ABOVE_BASELINE_MAX only when the numerator is 1; otherwise NOT_ABOVE_BASELINE_MAX. Ties are conservative. No calibrated p-value, confidence score, prediction, significance, safety or trend claim. The rank is descriptive: repeated observations, changing observation practices, archive caps, spatial/temporal dependence and unknown coverage can all drive the result. Five rows is an engineering minimum, not a statistically validated sample size. Multiple facilities are screened descriptively without inferential claims.

The exported report binds original bundle/source digests, policy ID, target and baseline dates, exact integer counts and reason/status for each facility. The independent Python verifier replays the original bundle and v0.7 history using its separate distance implementation, then recomputes rank comparisons using exact rational arithmetic. A matching replay is computation agreement, not scientific validation. Optional expected SHA-256 is a separately retained anchor, not authenticated origin. No private coordinates or evidence should be published. No live calls or paid resources.

Acceptance: the existing short synthetic fixture abstains; a manufactured 20-day example has one strictly above-baseline facility, one tied facility, and one zero-match facility. Test partial-day exclusion, insufficient rows, ties, conservative ranks, future observations exclusion, malformed/altered data and independently rehashed report changes. This is a retrospective software contract, not a prospective real-data evaluation. Before any empirical claim, collect a longer independently sourced archive, characterize coverage/duplicates and evaluate against prespecified comparators with held-out dates.

## Use

Serve the repository with `python -m http.server 8000` and visit `http://localhost:8000/anomaly.html`. Load the short synthetic example (expected abstention), or generate the manufactured example with `python scripts/anomaly_demo.py NEW_BUNDLE.json` and import it. Export the report; retain the original bundle. Verify with `python scripts/verify_earth_anomaly.py BUNDLE.json REPORT.json --expected-sha256 DIGEST` (optional independent digest). Tests: `node --test tests/anomaly.test.mjs` and `python -m unittest discover -s tests -p 'test_earth_anomaly.py' -v`. Browser checks use the original JavaScript method; Python is independent. Do not interpret an unflagged or abstained facility as safe.
